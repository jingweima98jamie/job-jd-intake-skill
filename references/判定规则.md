# 判定规则：命名规范、匹配度锚点、投递判定

## 一、命名与编号规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 文件夹 | `工作N+岗位名（公司简称）` | `工作12+数据运营（示例公司）` |
| 编号 N | 现有最大编号 + 1；历史空号不回填 | — |
| JD 截图 | `工作N_JD_岗位名_序号.png`；不同渠道重挂加渠道名 | `工作28_JD_AI产品运营_猎聘_1.png` |
| 背调文档 | `公司背调_公司简称.md`；高风险加 `_高风险`；含成长路径加 `_含成长路径` | `公司背调_游草网络_高风险.md` |
| 简历 | `姓名_岗位名_简历.html / .pdf` | — |
| 一家两岗 | 各建独立文件夹 | — |

**查重优先于编号**：同公司同岗的重挂（渠道不同、薪资微调）不新建文件夹，截图并入旧文件夹并在其背调文档头部补重挂记录。

## 二、匹配度四档锚点

逐条把 JD 要求对照 profile.md 的履历事实库，按硬要求命中情况锚定区间：

| 区间 | 标准 |
|---|---|
| 85-90% | JD 几乎是履历的同义改写，逐条命中，缺的只是业务域常识 |
| 70-80% | 主业命中 3 条以上，缺的是行业/业务域经验 |
| 55-70% | 核心能力可迁移，但缺关键实操（某个具体工具、某类增长手段、某行业经历） |
| <55% 或 — | 硬门槛不满足（年限翻倍、纯研发、完全陌生领域） |

写法要求：百分比后面必须跟"缺什么、用哪段经历去接"，不许只给数字。

## 三、投 / 不投 / 高风险

**升级信号**：JD 与履历同源、年包进入目标区间、甲方直招、公司口碑好、岗位刚更新。

**红旗：疑似虚假招聘**（命中 3 条以上按高风险处理）
- 注册时间 < 1 年
- 注册资本与标注规模矛盾（如 100 万资本挂几千人）
- 全网查无公开信息（无新闻、无点评、无经营痕迹）
- 中介代发（HR 头衔是"顾问/猎头"而非企业员工）
- "可远程"+ 高薪组合
- 话术出现"学历年限不限，以过往成绩为准"

→ 处理：**不投、不聊、不传简历**（简历含手机号与详细履历）。背调文档加 `_高风险`，写明理由 + 防范动作（不点链接、不扫码、不付任何"培训/保证金"费用）+ 正规替代渠道。

**红旗：方向错配**
- 纯研发岗硬门槛（特定编程语言/云原生/分布式/算法），与自身方向是两条路 → 不投不建简历，若用户问成长路径则写 `_含成长路径` 背调。

**降级**
- 硬门槛年限明显不够 → 练手投，明确标注"练手"。
- 乙方实施/驻场类 → 可投，但面试必问出差频率，频繁驻场则放弃。
- 薪资结构复杂（几薪、绩效占比）→ 写进面试必问，不要当成确定收入。

## 四、汇报口径

- 优先级只给三档：**第一梯队 / 第二梯队 / 练手**，并给建议投递顺序。
- 表格列：编号、岗位/公司、薪资（含几薪）、公司性质、匹配度、建议。
- 必须单独点出的提醒：薪资口径是否含绩效、出差频率、岗位是否还在招（更新时间太旧的先确认）、平台人数水分、虚假招聘警示。
- 结尾给一个明确的下一步问题（确认投递顺序？要不要出打招呼话术？）。
